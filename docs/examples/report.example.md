# Example report

**Purpose.** Show what the automations actually produce, so a reader knows what to
expect before running anything.

**Scope.** One plan report. The three files in this folder are a set:

| File | What it is |
| --- | --- |
| `report.example.md` | The rendered plan below. |
| `plan.example.json` | The same plan as JSON, written from the same object. |
| `apply.receipt.example.json` | The receipt from applying it. |

**Audience.** Anyone who has not yet run a command.

**Related documents**

- [command-model.md](../reference/command-model.md) — what each action and status means
- [verification-and-evidence.md](../process/verification-and-evidence.md) — how these artefacts are used

These files were **generated by the report writer itself**, not written by hand, so
they cannot drift from what the code produces. The data is invented: `APP_ALPHA`,
`contoso.com`, and a Board column rename mid-flight.

Note what the plan shows without being asked. Five operations already `ok` — the
intended shape of the application, not only its delta. One `protected`, because a
Service Connection exists and will not be touched. One `warning` about a Variable Group
key nobody declared, preserved rather than removed. And every operation carries a
reason written for the person approving it.
